# 02 — Prefactor：素材分類收斂成單一真實來源

**What to build:** 對使用者而言**什麼都沒發生**——`mm ingest` 的輸出一個字都不變，音訊與影片照樣落在 `unsupported`、圖片照樣落在 `unsupported`、訊息文字照樣。既有測試全綠，且不需要修改任何一條斷言。

改的是內部形狀：現在那個「這個檔為什麼不轉」的判定回傳的是一句訊息，後面的 Transcribe 需要的卻是「這是不是 Recording」這個分類。讓它回傳分類、訊息由呼叫端決定，Ingest 與 Transcribe 就能共用同一組副檔名清單與 mimetype 補漏規則。

不這樣做的話，Transcribe 會長出第二套「什麼算音訊」的判定，兩套遲早漂移——ADR-0003 已經把這組規則定死並寫了兩條路徑的測試，那是唯一真實來源。

先讓改動變簡單，再做那個簡單的改動。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 判定函式回傳分類（音訊/影片、圖片、可轉換），不再回傳訊息字串
- [ ] 「寫死的副檔名清單為地板、`mimetypes` 猜出的型別補漏」這個兩層結構原封不動保留，理由見 ADR-0003
- [ ] 不支援的訊息文字由 Ingest 端組出，內容與現在完全相同
- [ ] `mm ingest` 的 stdout JSON 逐欄位不變，包含 `unsupported` 每一項的 `message`
- [ ] 既有測試**一條斷言都不必改**就全綠——這是這張票有沒有做對的判準
- [ ] 沒有新增任何測試（行為沒變，就沒有新行為可測）
- [ ] 沒有順手改到判定以外的東西
